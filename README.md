# ななし律歌 FAN SITE 運用手順書

VSinger「ななし律歌」のファンによる非公式サイトです（非営利）。
このファイルは、サイトを **公開するまでの準備** と、**普段の更新のやり方** をまとめた手順書です。
細かい要件は同じフォルダの `要件.md`（GitHub には送らない設定）にあります。

---

## 用語のミニ解説

- **リポジトリ**：GitHub 上の「このサイトのファイル一式を入れる箱」。フォルダ 1 つ＝リポジトリ 1 つ。
- **コミット**：「ここまでの変更を 1 つの記録として保存する」操作。メモ（要約）を付けます。
- **プッシュ**：手元のコミットを GitHub に送る操作。
- **GitHub Pages**：リポジトリの中身をそのままウェブサイトとして公開してくれる GitHub の無料機能。
- **GitHub Desktop**：コミット・プッシュを画面のボタン操作でできる無料アプリ。黒い画面（ターミナル）は使いません。
- **キャッシュ**：ブラウザが一度読んだファイルをしばらく手元に保存する仕組み。更新がすぐ見えない原因になります。

## 1. 初回だけ：公開までの準備

所要時間はおよそ 30 分です。1-1 と 1-2 は自分で行う必要があります（アカウント作成やログインは本人が行う必要があるため）。

### 1-1. GitHub のアカウントを作る

1. <https://github.com/signup> を開く。
2. メールアドレス・パスワード・ユーザー名を決めて登録する。
   - **ユーザー名はそのままサイトの URL になります**（例：ユーザー名が `nanashi-fan` なら `https://nanashi-fan.github.io/nanashi-fansite/`）。半角英数字とハイフンだけが使えます。
   - ユーザー名は公開されるので、実名ではなくハンドル名にしてください。
3. 届いたメールで認証を済ませる。無料プラン（Free）で問題ありません。
4. **メールアドレスを公開しない設定**：GitHub の右上アイコン → Settings → Emails で、
   「Keep my email addresses private」と「Block command line pushes that expose my email」の両方にチェックを入れる。
   公開リポジトリでは、コミットごとの作者名とメールアドレスを誰でも見られるためです。

### 1-2. GitHub Desktop を入れてサインインする

1. <https://desktop.github.com/> から macOS 版をダウンロードし、アプリケーションフォルダへ入れて起動する。
2. メニューの **GitHub Desktop → Settings…（または Preferences…）→ Accounts** で **Sign in** を押し、ブラウザで 1-1 のアカウントにサインインする。
3. 同じ設定画面の **Git** タブで、Name をハンドル名、Email を 1-1 で用意された `xxxx@users.noreply.github.com` 形式のアドレスにする。これがコミットの署名になります。

### 1-3. このフォルダをリポジトリとして登録する

このフォルダ（`nanashi-fansite`）は、すでにリポジトリとして初期化してあります。

1. GitHub Desktop のメニュー **File → Add Local Repository…** を選ぶ。
2. **Choose…** で `デスクトップ/nanashi-fansite` を選び、**Add Repository** を押す。
3. 左側の「Changes」にサイトのファイルがずらっと並びます。Excel / Numbers のファイル全部（コピーや別名保存も含む）・`画像/`・`backup/`・`docs/`・`要件.md` は送らない設定なので、一覧に出なくて正常です。

### 1-4. 最初のコミットと、GitHub への送信（Publish）

1. 左下の **Summary** 欄に `サイト初版` と入力し、**Commit to main** を押す。
2. 上部の **Publish repository** ボタンを押す。
3. 出てきた画面で
   - **Name** は `nanashi-fansite` のまま（`404.html` のリンク先と CSS の読み込み先がこの名前を前提にしています）
   - **Keep this code private** の **チェックを外す**（無料プランで GitHub Pages を使うには公開リポジトリにする必要があります）
   - **Publish Repository** を押す。

> 注意：公開リポジトリは、送ったファイルの中身をすべて誰でも見られます。Excel や元画像を送らない設定にしているのはそのためです。今後も非公開のメモなどをこのフォルダに置かないでください。

### 1-5. GitHub Pages を有効にする

1. GitHub Desktop の上部 **View on GitHub**（または Repository → View on GitHub）でブラウザにリポジトリを開く。
2. 上のタブから **Settings** を開き、左メニューの **Pages** を選ぶ。
3. **Build and deployment → Source** が **Deploy from a branch** になっていることを確認する。
4. **Branch** で `main` を選び、右のフォルダは `/ (root)` のまま **Save** を押す。
5. 1〜3 分待ってから同じページを再読み込みすると、上部に **Your site is live at https://ユーザー名.github.io/nanashi-fansite/** と表示されます。これが公開 URL です。

### 1-6. 公開 URL をサイトに書き込む（共有カード用）

X や LINE にリンクを貼ったときに出る「カード」（画像付きの見出し）には、サイトの正式な URL が必要です。
6 つの HTML には仮の `https://USERNAME.github.io/nanashi-fansite/` が入っているので、ユーザー名が決まったら Claude Code に
「公開 URL は https://〇〇.github.io/nanashi-fansite/ なので HTML の USERNAME を置き換えて」と伝えてください（ターミナルなら次の 1 行でも置き換わります）。

```bash
cd "/Users/macbook/Desktop/nanashi-fansite" && sed -i '' 's/USERNAME\.github\.io/あなたのユーザー名.github.io/g' index.html news.html news-detail.html songs.html profile.html biography.html
```

### 1-7. 公開されたか確認する

公開 URL をブラウザで開き、トップページ・プロフィール・経歴・NEWS・歌唱リストが表示されれば完了です。
「404」と出る場合は、数分待ってから再読み込みしてください。それでも出ない場合は「5. 困ったとき」を見てください。

## 2. 普段の更新（直す → 送る → 反映）

更新はいつも同じ 3 ステップです。

1. **直す**：手元のファイルを編集する（下の 2-1〜2-4）
2. **送る**：GitHub Desktop でコミットしてプッシュする（2-5）
3. **反映**：1〜2 分で公開サイトに自動反映される（2-6）

### 2-1. NEWS を追加する

歌唱リストと同じく、Excel に書いて変換します。

1. `NEWS.xlsx` の「NEWS」シートに 1 行書き足して保存する（書き方は同じファイルの「使い方」シートにもあります）。
   - 列は 日付／見出し／詳細／リンクURL／リンクの文言／ID／メモ。1 行目の見出しは変えないでください（変換の目印です）。
   - サイトの一覧には「日付」と「見出し」だけが並び、行を押すと詳細ページ（「見出し」「詳細」とリンクボタン）が開きます。
   - 行は上が古く、下が新しい順です。新しい記事は一番下に足してください（順番が違っても、サイトでは日付の新しい順に自動で並びます）。
   - **日付** が今日より先の記事もそのまま表示されます。変換時に「今日より先です」の注意が出るので、年の打ち間違いでないか確認してください。
   - **詳細** はセル内で改行して書きます（Mac は Control+Option+Return）。空行で段落、行頭が ■ の行は小見出し、・ の行は箇条書き、＜会場＞のように＜ ＞で囲んだ行は項目名になります。最初の段落は、Google などの検索結果に出る説明文に使われます（X や LINE に貼ったときのカードは、サイト共通の見出し・説明になります）。
   - **リンクURL**（任意）は外部サイトなら新しいタブで開きます。サイト内のページは `./biography.html` のように書きます。リンクを 2 つ以上付けたい時は、リンクURL とリンクの文言をそれぞれセル内で改行して 1 行に 1 件ずつ書きます（上から順に対応し、ボタンが並びます）。
   - **ID**（任意）は半角英数字とハイフン。**注目スライドからリンクする記事や、X で共有した記事には必ず付けて、以後変えないでください。** 空欄なら日付から自動で付きますが、同じ日付の記事を増やすと番号がずれ、古いリンクが別の記事を指してしまいます。
   - **メモ** 列は自分用で、サイトには出ません。2 行目の灰色の行は記入例で、サイトには出ません（消しても OK）。
   - この Excel は GitHub には送られません（内部に作成者名が残るため）。手元の Mac とバックアップ（iCloud など）で管理してください。
2. 変換スクリプトを実行して `data/news.js` を作り直す。次のどちらかで行います。
   - Claude Code に「NEWS を更新して」と伝える。
   - または、ターミナルでこのフォルダに移動して次を実行する。

     ```bash
     python3 tools/convert_news.py
     ```

   実行すると `完了: 〇 件を書き出しました` と出ます。「注意」が出た場合は Excel の該当行を確認してください。
3. 2-5 の手順で GitHub へ送る。
- トップページには新しい順に 5 件、NEWS ページには全件が 10 件ずつのページ分けで表示されます（10 件以下のうちはページ送りは出ません）。1 ページの件数は `news.html` の `data-page-size="10"` の数字で変えられます。
- 一覧には日付と見出しだけが並び、行のどこを押しても詳細ページが開きます。
- NEWS に載せるのは活動全般のお知らせ（イベント出演、配信の節目、記念日など）と、Cover 動画・参加楽曲などの作品の公開です（作品は経歴にも載せます）。チャンネル登録者数は載せません。ショート動画は歌唱リストに載せます。他の方の作品に参加したときの言い方は「〇〇の楽曲「曲名」のVocalを担当」で統一します。
- Claude Code に頼む場合は「NEWS に追加して。日付〇〇、見出し〇〇、本文〇〇」と伝えれば、Excel への記入と変換まで直してもらえます。

### 2-2. 注目スライドを差し替える

`data/slides.js` を開き、3 件のうち差し替えたい 1 件を書き換えます。

```js
  {
    label: "ライブ",                                 // 左上の小さな分類ラベル（お知らせ / 動画 / ライブ など日本語で）
    title: "見出し",
    date: "2026.10.01",                              // 不要なら ""
    url: "https://www.youtube.com/watch?v=xxxxxxxxxxx",  // クリック先
    image: "",                                       // 空欄なら YouTube のサムネイルを自動表示
    until: "2026.10.15",                             // 任意。この日を過ぎると自動で消える
  },
```

- `url` が YouTube の動画・ショート・ライブなら、`image` を空欄にしておくだけでサムネイル（動画の縮小画像）が自動で表示されます。縦長のショート動画は、ぼかした背景の上に重ねて表示されます。
- YouTube 以外のリンクで画像が無い場合は、文字だけのパネルになります。
- **終わったライブの告知は差し替えるか、`until` に終了日を入れておくと自動で消えます。** 一番上に書いたものが 1 枚目に出るので、いちばん新しい話題を上にしてください。
- YouTube の共有リンクに付く `?si=…` は共有者を識別する目印なので、消して貼るのがおすすめです（残っていても動きます）。

### 2-3. プロフィール・経歴を直す

`data/profile.js` を開いて書き換えます。誕生日などの基本情報は `facts`、ハッシュタグは `tags` にまとまっています。
画像を差し替える時は、新しい画像を長辺 1200px 程度に縮小して `images/profile.jpg` という名前で上書きするか、別名で保存して `image` の値を変え、`imageWidth` / `imageHeight` を画像のピクセル数に合わせます。詳しくは `images/README.txt` を見てください。

経歴（年表）は、NEWS と同じく Excel に書いて変換します。

1. `経歴.xlsx` を開いて書き足し、保存する（書き方は同じファイルの「使い方」シートにもあります）。
   - 「経歴」シートが年表です。列は 日付／出来事／メモ。1 行目の見出しは変えないでください（変換の目印です）。
   - 行は上が古く、下が新しい順です。新しい出来事は一番下に足してください（順番が違っても、サイトでは日付順に自動で並びます）。
   - 表示は「10月1日」のように月日だけになり、年ごとに自動でまとまります。文末は「〜を公開。」「〜に出演。」のように言い切りの形にそろえると見た目が整います。出来事のセル内で改行（Mac は Control+Option+Return）すると、サイトでもそこで行が変わります。
   - 「紹介文」シートの「紹介文」の行がページ冒頭の文、その下の行（Live2D のクレジットなど）が紹介文の下に小さく出ます。クレジットが不要なら行を消します。
   - 2 行目の灰色の行は記入例で、サイトには出ません。**メモ** 列は自分用です。
   - この Excel は GitHub には送られません（内部に作成者名が残るため）。手元の Mac とバックアップ（iCloud など）で管理してください。
2. 変換スクリプトを実行して `data/biography.js` を作り直す。次のどちらかで行います。
   - Claude Code に「経歴を更新して」と伝える。
   - または、ターミナルでこのフォルダに移動して次を実行する。

     ```bash
     python3 tools/convert_biography.py
     ```

3. 2-5 の手順で GitHub へ送る。
- 経歴に載せるのは「作品に関わるもの」（Cover 動画、参加楽曲、ライブ出演、歌枠リレーなど）。作品の公開は NEWS にも載せます。登録者数・収益化・誕生日など活動全般の出来事は NEWS だけに書きます。ショート動画は初投稿のみ載せています。

### 2-4. 歌唱リストを更新する

1. `歌唱リスト.xlsx` の「歌唱リスト」シートに行を追加して保存する。
   - 列の順番と 1 行目の見出しは変えないでください（変換の目印です）。
   - 同じ曲を歌枠と動画の両方で公開した場合は、1 行ずつ別の行に書きます。
   - 同じ日の曲は Excel の行順でサイトに並びます。歌枠は歌った順に書いてください。
   - G 列「よみ」には、曲名の読みをひらがなで入れます（「五十音順」で並べる時に使います）。漢字で始まる曲名だけで十分です。ひらがな・カタカナで始まる曲は空欄で構いません。
     同じ曲を 2 回目以降に書く時は、読みを空欄にしても前の行の読みが自動で使われます。
   - 歌枠（配信アーカイブ）は、曲ごとに 1 行ずつ、YouTube の共有機能で作った時間指定つきリンク（`&t=秒数` が付いたもの）を貼ります。同じ配信の URL が複数行に並んでも問題ありません。
   - この Excel は GitHub には送られません（内部に作成者名が残るため）。手元の Mac とバックアップ（iCloud など）で管理してください。
2. 変換スクリプトを実行して `data/songs.js` を作り直す。次のどちらかで行います。
   - Claude Code に「歌唱リストを更新して」と伝える。
   - または、ターミナルでこのフォルダに移動して次を実行する。

     ```bash
     python3 tools/convert_songs.py
     ```

   実行すると `完了: 〇 件を書き出しました` と出ます。「注意」が出た場合は Excel の該当行を確認してください。
   初めて実行したときに「コマンドライン・デベロッパ・ツール」の導入を求められたら「インストール」を押して待ってください（一度だけ）。
   さらに内容の矛盾（空欄・日付・URL の重複・読みの抜けなど）を調べたい時は、次を実行します（数秒）。`--online` を付けると YouTube と突き合わせ（動画の存在・タイトル・公開日）も行います（数分かかります）。

     ```bash
     python3 tools/check_songs.py
     ```

     ```bash
     python3 tools/check_songs.py --online
     ```

3. 2-5 の手順で GitHub へ送る。歌唱リストのページには変換した日が「最終更新」として自動で表示されます。

### 2-5. GitHub へ送る

1. GitHub Desktop を開くと、左側の「Changes」に変更したファイルが並びます。
2. 左下の **Summary** に短いメモ（例：`NEWS 追加`、`歌唱リスト更新`）を入力し、**Commit to main** を押す。
3. 上部の **Push origin** を押す。これで GitHub に送信されます。

### 2-6. 反映を確認する

- プッシュから 1〜2 分で公開サイトが更新されます。
- ただし、一度開いたことのあるブラウザは古いファイルを最大 10 分間手元に残します（キャッシュ）。すぐ確認したい時は、Mac では **⌘ + Shift + R**（キャッシュを無視して再読み込み）か、シークレットウィンドウで開いてください。スマホは 10 分ほど置いてから開き直してください。

## 3. 公開前に手元で確認する方法

- `index.html` をダブルクリックするとブラウザで開き、公開後と同じ見た目を確認できます（データファイルは JS 形式にしてあるので、この方法でも検索・スライドが動きます）。
- 注目スライドの YouTube サムネイルはインターネット経由で表示されるため、オフラインでは表示されません。

## 4. 画像を追加・差し替えるとき

1. 元画像を `画像/` フォルダに保存する（このフォルダは GitHub に送られません）。
2. 長辺 1200px 程度・JPEG 品質 80 に縮小したものを `images/` に保存する（Claude Code に「縮小して images に置いて」と伝えてもよい）。
3. スライドで使う場合は `data/slides.js` の `image` に、プロフィールなら `data/profile.js` の `image` に `"images/ファイル名"` と書く。
4. **許諾の記録**：公式画像（ご本人や主催のイラスト・写真）を使う場合は、誰から・いつ・どの範囲で許可を得たかを `docs/画像の許諾記録.md`（GitHub には送らない）に書き残す。公開される `images/README.txt` には相手の名前や連絡の内容を書かない。権利者から削除の要望があれば、`image` を `""` に戻せば表示が消えます。

現在、プロフィール画像（ご本人の X 投稿画像）とライブのキービジュアル（他の出演者も写っている）を使っています。どちらも掲載の許諾を得ています（2026-10-03 確認、記録は `docs/画像の許諾記録.md`。「誰から・どの手段で」の欄は制作者が記入してください）。

## 6. 仕様メモ

- 注目スライドは 3 件を 5 秒ごとに自動で切り替え、最後まで行くと先頭に戻ります。マウスを乗せている間・キーボードで操作している間は止まります。スマホではスワイプではなく、左右の矢印とドットをタップして送ります。OS で「視差効果を減らす」を設定している人には自動送りをしません。ドット行の右端の ❙❙ ボタンで自動送りを止められ、もう一度押すと再開します。
- 歌唱リストは 1 ページ 50 件でページ分けされ、リストの上下にあるページ送り（前へ／番号／次へ）で移動します（スマホでは下側だけ）。検索・絞り込み・並び替えをすると 1 ページ目に戻ります。絞り込みのボタンは、選択中のものをもう一度押すと解除され「すべて」に戻ります。件数を変えたい時は `js/songs.js` の `PAGE_SIZE` の数字を変えます。
- 歌唱リストは「新しい順」が既定で、「五十音順」にも切り替えられます。五十音順では G 列「よみ」の読みを使います。同じ日の曲は Excel の行順です。
- 曲名・アーティストは部分一致で検索でき、ひらがな／カタカナ、全角／半角、大文字／小文字、記号（`*` や `.` や空白）の違いは無視します。種類（音源／弾き語り／アカペラ）と形式（歌枠／動画／Short）は組み合わせて絞り込めます。アーティスト名を押すと、そのアーティストの曲だけに絞り込めます（「A & B」のようなコラボ表記の曲も含みます。検索欄を打ち直すと解除されます）。
- NEWS は一覧（トップ 5 件・NEWS ページ 10 件ずつ。日付と見出しだけを表示し、行全体が詳細ページへのリンク）と詳細ページ（`news-detail.html?id=記事ID`）で構成されます。元データは `NEWS.xlsx` で、`tools/convert_news.py` が `data/news.js` に変換します（歌唱リストと同じ仕組み）。
- 経歴ページは `data/biography.js` の出来事を日付の古い順に並べ、年ごとに見出しを付けて表示します（ヨルシカ公式サイトの BIOGRAPHY を手本にした書式）。元データは `経歴.xlsx` で、`tools/convert_biography.py` が変換します。
- 少しスクロールすると右下に「ページ上部へ戻る」ボタンが現れ、クリックで先頭に戻ります。
- 文字はすべて端末に入っているゴシック体（Mac/iPhone はヒラギノ、Windows は游ゴシック／メイリオ）で表示し、Web フォントは読み込みません。
- SNS のリンク先は `https://x.com/__77shi`、`https://www.youtube.com/@nanashi_77shi`、`https://www.tiktok.com/@__.nanashi.__` です。`__`（アンダースコア 2 つ）はアカウント名の一部なので、編集する時は欠けないよう注意してください。
- フッターの免責文は「ご本人とは関係ありません」としています（個人勢のため、当初の要件にあった「および所属」を外しました）。あわせて画像・名称の権利と削除対応の一文を入れています（連絡先のリンクは置いていません）。
- NEWS は日付に関係なく全記事を表示します（先の日付の記事もそのまま出ます）。詳細ページの見出し・説明文は記事ごとに切り替わりますが、X や LINE のカードはサイト共通の文になります。
- 当初の要件からの変更点（並び順、ページ分け、追加ページ、画像の使用など）は `要件.md` の「10. 改訂履歴」にまとめています。
